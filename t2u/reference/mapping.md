# Three.js → Unity mapping reference

## Coordinates (most common source of bugs)
- Three.js: right-handed, Y up, camera looks toward -Z. Unity: left-handed, Y up, forward = +Z.
- Use ONE conversion function everywhere, never ad-hoc sign flips:
  - Position: `(x, y, z) → (x, y, -z)`
  - Quaternion: `(x, y, z, w) → (-x, -y, z, w)`
  - Euler from Three.js: convert to quaternion in Three.js space first, then apply the quaternion rule. Never copy euler angles directly (rotation order differs: Three.js default XYZ, Unity ZXY).
  - Scale: unchanged.
- Exception: models imported from GLB via glTFast are already converted by the importer. Do NOT flip them again — only flip data you export yourself (positions/rotations in scene JSON, level data, logic vectors).
- Verify with a test scene: arrows for +X (red), +Y (green), forward (blue), plus one asymmetric object. Screenshot in both engines from the same camera.
- Angles: Three.js uses radians, Unity Transform/Mathf uses degrees in many APIs. Convert explicitly (`Mathf.Rad2Deg`).
- Units: keep 1 unit = 1 meter. If the Three.js game uses another scale, record the factor in PLAN.md.

## Concept mapping
| Three.js / JS | Unity / C# |
|---|---|
| `Scene` | Scene (.unity) |
| `Object3D` / `Group` | empty GameObject |
| `Mesh` (geometry + material) | GameObject + MeshFilter + MeshRenderer, usually a Prefab |
| `MeshStandardMaterial` | URP/Lit (metalness → Metallic, roughness → Smoothness = 1 - roughness) |
| `MeshBasicMaterial` | URP/Unlit |
| `MeshPhongMaterial` / `MeshLambertMaterial` | URP/Simple Lit |
| `ShaderMaterial` / onBeforeCompile | Shader Graph (rewrite; describe the visual effect first) |
| `PerspectiveCamera` (fov = vertical) | Camera, Field of View axis = Vertical, same near/far |
| `OrthographicCamera` | Camera Orthographic, size = (top - bottom) / 2 |
| `DirectionalLight` / `PointLight` / `SpotLight` / `AmbientLight` / `HemisphereLight` | Light (Directional/Point/Spot) / Environment lighting (Color or Gradient) |
| light.intensity | not 1:1; tune visually, write chosen values in PLAN.md |
| `renderer.toneMapping` / outputColorSpace | URP Volume Tonemapping (ACES/Neutral); Linear color space for lit 3D, Gamma for 2D sprite/web-canvas looks |
| `Fog` / `FogExp2` | RenderSettings fog Linear / Exponential Squared |
| `AnimationMixer` + clips | Animator + Animator Controller (or Animation component for simple cases) |
| `InstancedMesh` | GPU instancing on material, or Graphics.RenderMeshInstanced |
| `Raycaster` | Physics.Raycast (needs Colliders) |
| `requestAnimationFrame` loop | MonoBehaviour Update / FixedUpdate; logic tick in a GameLoop component |
| `clock.getDelta()` | Time.deltaTime (fixed step: Time.fixedDeltaTime) |
| `setTimeout` / `setInterval` | Coroutine, or timers ticked inside the logic layer (preferred for determinism) |
| Promise / async | UniTask or C# async/await (avoid in core logic) |
| EventEmitter / custom events | C# `event Action<T>` or a small EventBus class |
| `Math.random()` | `T2U.Kit.SeededRandom` (mulberry32, same as the harness) — never System.Random when replays must match |
| `Math.sin/cos/exp/log/hypot` | `T2U.Kit.JsMath.*` (bit-exact with Chrome); `Math.round` → `Js.Round`; the template's `pow(b, e)` → `Js.Pow` |
| GSAP / tween.js | DOTween or LitMotion |
| cannon-es / rapier / ammo | Unity Physics (PhysX) — behavior differs; re-tune, do not expect frame-exact match |
| HTML/CSS UI overlay | uGUI Canvas + TextMeshPro (default), Canvas Scaler = Scale With Screen Size |
| keyboard/mouse/touch events | Input System package (Pointer, Touchscreen, Keyboard) |
| Howler / WebAudio | AudioSource + AudioMixer |
| localStorage | PlayerPrefs (simple) or JSON file in Application.persistentDataPath |
| JSON config files | ScriptableObject assets, generated by an editor importer from the same JSON |
| `dispose()` | Destroy(); pooling for frequently spawned objects |
| `object.visible = false` | `gameObject.SetActive(false)` or `renderer.enabled = false` |
| `userData` | fields on a MonoBehaviour component |

## TypeScript/JS → C# pitfalls
- `number` is double; in C# choose `float` for gameplay/vectors, `int` for counters/indexes, `double` only if precision matters. Watch integer division (`5/2` is 2 in C#).
- `===`/truthiness: `if (x)` on numbers/strings/null must become explicit checks.
- `undefined` vs `null`: use nullable types or explicit sentinels.
- Array methods (`map/filter/reduce/find/splice/sort`): use List<T> + LINQ outside hot loops; plain loops in Update (no per-frame allocations).
- `Array.sort` comparator semantics and stability differ; Unity's List.Sort is unstable → add a tiebreaker if order matters.
- Object literals / dynamic keys → classes/structs or Dictionary<string, T>.
- Closures capturing loop variables, `this` binding → check carefully.
- `%` with negative numbers behaves the same in both, but `Math.floor` vs `(int)` cast differ for negatives (use Mathf.FloorToInt).
- `Math.atan2(y, x)` = `Mathf.Atan2(y, x)` (radians). Check if Z was flipped when computing angles in the XZ plane.
- String formatting / number formatting for UI: use invariant culture.

## Unity project conventions (what the company team expects)
- Unity 6 LTS, URP (Mobile renderer, SRP Batcher off for sprite games), Gamma color space for 2D/web-like games (Linear for 3D PBR), Input System, TextMeshPro, T2U Kit package (Packages/com.t2u.kit).
- Folders:
```
Assets/_Game/
  Scripts/Core/        # pure C#, no UnityEngine dependency where possible (asmdef: Game.Core, noEngineReferences if feasible)
  Scripts/View/        # MonoBehaviours: rendering, animation, VFX, audio (asmdef: Game.View)
  Scripts/UI/          # screens, HUD (asmdef: Game.UI)
  Scripts/Infra/       # save, SDK wrappers, services (asmdef: Game.Infra)
  Editor/              # importers, scene builders, menu tools (asmdef: Game.Editor, Editor only)
  Tests/EditMode/      # NUnit tests for Core (asmdef: Game.Tests)
  Data/                # ScriptableObjects generated from JSON
  Prefabs/  Scenes/  Art/Models/  Art/Materials/  Art/Textures/  Audio/  VFX/
```
- One class per file, file name = class name, namespace `Game.<Folder>`.
- PascalCase for types/methods/public members, `_camelCase` for private fields, `[SerializeField] private` instead of public fields.
- No `GameObject.Find` / `FindObjectOfType` in gameplay; wire references via inspector or a simple bootstrap/composition root.
- No `new` allocations, LINQ, or string concatenation inside Update loops.
- Comments in English (for the team), short XML summary on public classes.
